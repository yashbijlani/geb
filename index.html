a machine for looking at itself

What happens when a formal system tries to settle every question it can express?

A long-form construction of Gödel’s First Incompleteness Theorem. We begin with marks and end with a sentence whose meaning exceeds the machine that generated it.

01 / the object level toy model

Start with a world that does not understand itself.

02 / derivation standard

A theorem is a history, not a feeling.

Inside a formal system, the initial question is not “is this true?” but “is there a permitted finite derivation that reaches this string?”

Select a step. The machine marks the exact rule that made it possible. A proof is a finite object that can be checked.

03 / deciding theoremhood standard

Generating proofs is not the same as deciding whether a string is a theorem.

A proof generator can search for a derivation. A proof checker can confirm one. But a decision procedure must always halt with yes or no for an arbitrary candidate.

04 / the turn inward geb

Self-reference is not a slogan; it is a substitution.

First a statement points to another statement. Then it points to a description of a statement. The dangerous move is when the description is allowed back into the construction as input.

statement→another statement
statement→its description
statement↺its own description

The loop is not the word “self.” It is a real substitution in which a description is fed back into the construction.

05 / syntax becomes arithmetic geb + standard

Give every symbol a number.

06 / the great trick standard

A description can be applied to the thing it describes.

Diagonalization turns a formula with a free variable into a sentence that receives its own code. This is not an infinite mirror; it is a one-step substitution that closes the loop.

07 / construct G standard / pedagogical model

Now make the system talk about its own proofs.

Let ProofS(p, q) mean that p codes a valid proof in S of the formula with code q. Let ProvS(q) mean “there exists a proof p for q.”

G ↔ ¬ProvS(⌜G⌝)

In the intended arithmetic reading, G says: “this sentence is not provable in S.” The sentence is built by encoding and diagonalization, not simply announced.

system S
proof predicate
self-code ⌜G⌝
G : ¬ProvS(⌜G⌝)

09 / two viewpoints standard

Truth and provability are different relations.

Inside S, the question is whether a proof exists. Outside S, we can judge the sentence in the intended arithmetic interpretation. Under the relevant soundness assumptions, G is true even though it is not provable in S.

inside Sno proof found
external arithmetic viewG is true under the intended interpretation

Slide between the relation inside the system and the relation outside it.

11 / a different substrate standard

Replace proofs with programs.

The Halting Problem is not Gödel’s theorem, but it is built from the same diagonal pattern. A program asks whether another program halts, and then gets fed its own description.

HALT?(P, x) oracle waiting 
D(P):
  if HALT?(P, P) = HALTS:
      loop forever
  else:
      halt

The hypothetical oracle looks perfect until D is given its own code.

program→oracle→behavior

12 / related, not identical standard

Two machines, one family resemblance.

Gödel uses arithmetic coding and proof predicates. Turing uses programs, code, and halting behavior. Their substrates differ, but the diagonal obstacle is structurally the same.

Gödel

syntax → code → self-reference → undecidable sentence

Turing

program → code → self-reference → undecidable behavior
