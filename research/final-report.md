# Final report

## Thesis

The project should not translate GEB into a polished book website. It should treat the book as a system of structural relations and translate that system into a computational experience where the user can perceive the book’s underlying logic directly.

The key is not to summarize the text. The key is to expose the operations the text performs:

- rule formation
- symbol transformation
- self-reference
- recursion
- level crossing
- meaning via relation
- tangled hierarchy

## The decisive insight

The book’s real subject is not merely Gödel, Escher, and Bach as individual figures. It is the shared dynamic among them: an underlying system that is capable of referring to, transforming, and destabilizing itself.

This is why the project must build experiments around mechanisms, not around exposition.

## Why earlier prototypes were not enough

The early prototypes were attractive but conceptually weak because they treated GEB as a set of topical labels to be displayed. That did not produce a genuinely new form of understanding.

A website that simply “contains” the book’s concepts does not help the user perceive the structural relation among them. The user must be able to manipulate the relationships themselves.

## What the research showed

From the extracted source and chapter map, the strongest organizing pattern is:

- formal systems create worlds of derivation
- meaning is relational, not intrinsic
- self-reference produces paradox and insight
- recursion generates complexity from ordered repetition
- levels of description can be nested and then folded back on each other
- tangled hierarchies produce strange loops
- minds, systems, and machines exist in the same conceptual neighborhood

This is the heart of the book, and it is what the final experience should preserve.

## Strongest representation choice

The strongest direction is a laboratory-like interface built around a shared computational substrate. The book’s repeated structures should be represented in multiple modes simultaneously:

1. formal-string view
2. recursive-graph view
3. visual hierarchy or loop chamber
4. musical transformation mode
5. self-reference and proof mode

The same underlying rule should appear as different representations, so the user can observe identity across transformation.

This makes the experience feel like the book itself: a structure that refuses to stay at one level and instead keeps reappearing under different guises.

## Recommended final environment structure

The final site should be a single research instrument rather than a set of summary panels.

### Primary blocks
- Rule world: manipulate a formal system and watch derivations evolve
- Self-reference engine: create statements that point back to their own conditions
- Recursion lab: compare tree, sequence, and nested structure forms
- Strange-loop chamber: represent levels folding back into themselves
- Bach machine: transform motifs and hear identity across variation

### Additional principles
- Minimal explanatory copy; let interaction reveal the logic
- Shared state across modules so all experiments relate to the same underlying structure
- Visual hierarchy where the user can move between levels while preserving the previous state
- Temporal transformation: processes should happen over time, not just as static diagrams
- Meaning appears through relation and comparison, not through labels alone

## What to avoid

- chapter summary pages
- generic editorial cards
- purely decorative motion studies
- generic “AI-looking” dashboard aesthetics
- over-polished prose that explains away the uncertainty of the book

## Final design goal

The final website should make the user feel like they are operating inside a system that is trying to understand itself.

That is the closest possible computational translation of GEB’s central challenge: not just to explain paradox, but to build a space where the structure of paradox, recursion, and self-reference becomes perceptible as a lived phenomenon.
